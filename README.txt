KASHIE — ORIGINAL DESIGN + ADMIN COMMAND CENTRE + SECURE API FOUNDATION + PWA

This release was assembled from KASHIE_ORIGINAL_PREVIEW_CORRECTIONS_NETLIFY.zip and the original-design Admin Command Centre release candidate. It does NOT use the excluded V2 design. The original KASHIE page and metallic emblem are retained; a server-backed production admin view and installable PWA shell have been added.

WHAT IS INCLUDED
- Original KASHIE front-end design, metallic emblem, artist imagery, and the corrections already approved.
- Admin command-centre view backed by database queries when running in production mode.
- Secure server-side admin sign-in using a bcrypt password hash and an HTTP-only session cookie.
- PostgreSQL schema for users, artists, artworks, events, orders, payments, payouts, announcements, audit logs, commissions, and complaints.
- Admin API views/actions for artists, artworks, orders, events, announcements, payments/refunds, payouts, commissions, complaints, user access, settings, and audit logs.
- Paystack checkout initialization and HMAC-verified payment webhooks. Successful payments are only confirmed by a valid provider webhook with a matching reference, amount, and currency.
- Platform fee tracking (default 4.5%, configurable through PLATFORM_FEE_BPS).
- PWA manifest and service worker. The service worker explicitly does not cache API responses.
- Render blueprint to host the Node service and PostgreSQL database.

IMPORTANT: NOT A ONE-CLICK LIVE PAYMENT LAUNCH
The bundle is a production-oriented release candidate, not a claim that your live site is already connected to real records. Real production operation requires you to deploy the Node service with PostgreSQL, set the private environment variables, configure Paystack, configure the provider webhook, test the whole payment/refund lifecycle in Paystack test mode, and review legal/privacy/security requirements. Never put secret keys in index.html or share them in chat.

DEPLOYMENT OVERVIEW (RECOMMENDED: RENDER)
1. Keep your current Netlify site untouched while testing.
2. Upload this ZIP to a new private GitHub repository, or extract it locally and push the files to a new repository. Keep index.html at the project root.
3. In Render, create a Blueprint from render.yaml (or create a Node web service and PostgreSQL database). The Node service runs `npm install` then `npm start`.
4. In the service environment settings, set:
   - ADMIN_EMAIL: the administrator email you control.
   - ADMIN_PASSWORD_HASH: output from the password-hash command below.
   - APP_ORIGIN: the exact HTTPS origin of the deployed service, with no trailing slash.
   - PAYSTACK_SECRET_KEY: a private Paystack TEST secret key for initial testing.
   - PAYSTACK_PUBLIC_KEY: your Paystack test public key (kept server-side here; never use a secret key in browser code).
   - SESSION_SECRET is generated by the Render blueprint; do not replace it with a short value.
5. Generate the password hash on a trusted computer with Node installed:
   `node server/hash-password.js "a-long-unique-password-of-your-own"`
   Put the resulting hash into ADMIN_PASSWORD_HASH. Do not use the sample phrase literally. Do not send the password or hash to anyone.
6. After deployment, open `https://YOUR-SERVICE-ORIGIN/api/health` and check for `{"ok":true,...}`.
7. In the Paystack dashboard, configure the webhook URL as:
   `https://YOUR-SERVICE-ORIGIN/api/webhooks/paystack`
   Enable the relevant successful-charge and refund events supported by your Paystack account. Use test keys and test transactions first.
8. Sign in using the Administrator option. On the server-backed service, non-admin demo sign-ins are disabled. The administrator dashboard should say LIVE DATABASE; if it says simulation, you are on the static demo, not the connected service.
9. Test a successful payment, wrong-amount webhook, duplicate webhook, failed payment, refund request and refund webhook before moving to live keys.
10. Only after verification should you decide whether to point a domain or promote the service publicly.

PAYMENTS AND FINANCIAL SAFETY
- Amounts are stored in minor units (for NGN, kobo). The checkout endpoint accepts `amountMinor`.
- A browser redirect is not proof of payment. A verified signed Paystack webhook is used to mark an order paid.
- Refunds are requested through Paystack and are only marked refunded when a provider refund webhook is received.
- Payouts are recorded as pending/processing/paid records; this package does NOT initiate bank transfers. Connect and test a permitted payout provider and reconciliation workflow before paying artists.
- Platform fees are tracked at the configured basis-point rate; accountant/legal review should confirm the fee model and refund treatment.

PWA / APP
The manifest and service worker make the HTTPS website installable on supported mobile browsers. This is an installable web app (PWA), not yet a published Play Store or Apple App Store application. API responses are not cached by the service worker.

SCOPE / REMAINING WORK BEFORE A GENERAL PUBLIC LAUNCH
- Public buyer/artist registration, password recovery, email verification, and role approval workflow are not enabled in this release; administrator access is the only production sign-in.
- Artwork and artist records can be reviewed in the admin API, but permanent image/file storage and upload moderation need a storage provider.
- Public checkout must be connected to a real cart/artwork selection flow and tested end-to-end; the API checkout endpoint is a secure foundation, not a finished storefront checkout experience.
- Payouts are not automatic; do not promise artists a transfer until a payout provider and reconciliation are implemented.
- Run a security review, privacy/data-protection review, backup/restore test, monitoring setup, and accessibility/mobile QA before opening to the public.

STATIC PREVIEW
If this folder is uploaded to Netlify as static files only, the API and real database will NOT run there. The static preview still shows demo portals; all sample numbers/activity are illustrative and are not actual sales, payments, users, or bank data. Use the Node service for production mode.
